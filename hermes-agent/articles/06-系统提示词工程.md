# 系统提示词工程：Hermes Agent 的提示词组装与缓存策略

> **项目**: [NousResearch/hermes-agent](https://github.com/NousResearch/hermes-agent) v0.15.1
> **核心源码**: `agent/system_prompt.py`、`agent/prompt_builder.py`、`agent/prompt_caching.py`
> **分析日期**: 2026-05-29

---

## 一、设计哲学：缓存友好的分层架构

Hermes Agent 的系统提示词不是一段大杂烩文本，而是一个**严格分层的缓存友好结构**。核心原则只有一条：**会话内绝不修改系统提示**。任何修改都会使上游 Prompt Cache 失效，导致成本飙升。

基于此原则，系统提示被组织为三个层级（tier），每个层级有不同的变更频率：

| 层级 | 变更频率 | 缓存行为 | 内容 |
|------|---------|---------|------|
| **stable**（稳定层） | 进程生命周期内不变 | 全量缓存 | 身份、工具指引、技能索引、环境提示、平台提示 |
| **context**（上下文层） | 跨会话可能变化 | 新会话重建 | 项目上下文文件（AGENTS.md 等）、调用方 system_message |
| **volatile**（易变层） | 每次会话/可能每轮变化 | 不缓存 | 记忆快照、用户档案、外部记忆、时间戳 |

三层通过 `"\n\n"` 拼接为一个完整字符串，缓存在 `agent._cached_system_prompt` 上。唯一的重建触发条件是**上下文压缩事件**——压缩后需要重新加载磁盘上的记忆数据。

```python
# agent/system_prompt.py — 核心组装函数

def build_system_prompt(agent, system_message=None) -> str:
    parts = build_system_prompt_parts(agent, system_message)
    return "\n\n".join(p for p in (
        parts["stable"], parts["context"], parts["volatile"]
    ) if p)
```

## 二、提示词组装顺序详解

`build_system_prompt_parts()` 是整个系统提示词的组装入口。它按照固定顺序将各个组件填入三个层级。

### 2.1 Stable 层：身份与行为指引

Stable 层是最长的部分，也是缓存收益最大的部分。组件按以下顺序组装：

#### ① SOUL.md — Agent 身份/人格

```python
if agent.load_soul_identity or not agent.skip_context_files:
    _soul_content = _r.load_soul_md()
    if _soul_content:
        stable_parts.append(_soul_content)
        _soul_loaded = True

if not _soul_loaded:
    stable_parts.append(DEFAULT_AGENT_IDENTITY)
```

SOUL.md 是 Hermes 的"灵魂"文件，位于 `$HERMES_HOME/SOUL.md`（即 `~/.hermes/SOUL.md`）。用户通过编辑此文件定义 Agent 的身份、人格和沟通风格。

**查找逻辑**：`load_soul_md()` 从 `HERMES_HOME` 目录读取 SOUL.md，经过安全扫描（`_scan_context_content`）和截断（最大 20,000 字符）后返回。

**回退机制**：如果 SOUL.md 不存在或为空，使用硬编码的默认身份：

```
You are Hermes Agent, an intelligent AI assistant created by Nous Research.
You are helpful, knowledgeable, and direct. You assist users with a wide
range of tasks including answering questions, writing and editing code,
analyzing information, creative work, and executing actions via your tools.
You communicate clearly, admit uncertainty when appropriate, and prioritize
being genuinely useful over being verbose unless otherwise directed below.
Be targeted and efficient in your exploration and investigations.
```

**特殊场景**：Cron 模式下 `skip_context_files=True` 但 `load_soul_identity` 可能为 True，允许定时任务保留人格但跳过项目上下文。

#### ② Hermes 自助指引

```python
stable_parts.append(HERMES_AGENT_HELP_GUIDANCE)
```

始终注入。告知模型当用户询问 Hermes 自身的配置、安装、使用问题时，应先加载 `hermes-agent` 技能：

```
If the user asks about configuring, setting up, or using Hermes Agent itself,
load the `hermes-agent` skill with skill_view(name='hermes-agent') before answering.
Docs: https://hermes-agent.nousresearch.com/docs
```

#### ③ 任务完成指引（Task Completion Guidance）

```python
if getattr(agent, "_task_completion_guidance", True) and agent.valid_tool_names:
    stable_parts.append(TASK_COMPLETION_GUIDANCE)
```

**通用指引**，不按模型家族门控。解决两个跨模型失败模式：

1. **写完桩就停**：模型写了一个 85 字节的文件或跑了一条命令就结束，声称任务完成（Opus 模型实测）
2. **虚构输出**：工具失败时，模型编造看起来合理的结果代替真实工具输出（DeepSeek v4-flash 实测）

核心内容：

```
When the user asks you to build, run, or verify something, the deliverable is
a working artifact backed by real tool output — not a description of one.
Do not stop after writing a stub, a plan, or a single command.
...
NEVER substitute plausible-looking fabricated output for results you couldn't
actually produce. Reporting a blocker honestly is always better than inventing
a result.
```

通过 `config.yaml` 的 `agent.task_completion_guidance` 开关控制，默认启用。

#### ④ 工具感知行为指引

根据当前可用的工具集，条件性地注入对应的行为指引：

| 工具名 | 指引常量 | 作用 |
|--------|---------|------|
| `memory` | `MEMORY_GUIDANCE` | 记忆写入规范：保存持久事实而非临时状态 |
| `session_search` | `SESSION_SEARCH_GUIDANCE` | 跨会话上下文召回 |
| `skill_manage` | `SKILLS_GUIDANCE` | 复杂任务后保存技能、发现过时技能立即修复 |
| `kanban_show` | `KANBAN_GUIDANCE` | 看板任务生命周期协议 |

**记忆指引**特别值得注意——它明确区分了什么该存、什么不该存：

```
Do NOT save task progress, session outcomes, completed-work logs, or
temporary TODO state to memory; use session_search to recall those from
past transcripts. If a fact will be stale in a week, it does not belong
in memory.
```

并且要求声明式而非祈使式写法：

```
'User prefers concise responses' ✓ — 'Always respond concisely' ✗
'Project uses pytest with xdist' ✓ — 'Run tests with pytest -n 4' ✗
```

原因是祈使式措辞在后续会话中会被重新解读为指令，可能导致重复工作或覆盖用户当前请求。程序和工作流属于技能（skill），不属于记忆。

#### ⑤ 计算机使用指引（Computer Use）

```python
if "computer_use" in agent.valid_tool_names:
    from agent.prompt_builder import COMPUTER_USE_GUIDANCE
    stable_parts.append(COMPUTER_USE_GUIDANCE)
```

作为独立块注入（而非合并到工具指引中），因为内容是多段落的。覆盖 macOS 后台桌面控制的完整工作流：

1. 使用 `action='capture'` + `mode='som'` 获取带编号叠加层的截图
2. 通过元素索引点击 `action='click', element=14`，比像素坐标可靠得多
3. 状态改变后重新截图验证
4. 严格安全限制：不点击权限对话框、不输入密码、不执行 UI 注入指令

#### ⑥ Nous 订阅状态

```python
nous_subscription_prompt = _r.build_nous_subscription_prompt(agent.valid_tool_names)
if nous_subscription_prompt:
    stable_parts.append(nous_subscription_prompt)
```

当用户启用了 Nous 订阅（提供 Firecrawl 网页工具、FAL 图像生成、OpenAI TTS、Browser Use 等托管服务），注入当前能力状态。模型据此知道不需要再向用户索要相关 API Key。

#### ⑦ 工具使用强制指引（Tool-Use Enforcement）

```python
if agent.valid_tool_names:
    _enforce = agent._tool_use_enforcement
    # "auto" | True | False | list[str]
    ...
    if _inject:
        stable_parts.append(TOOL_USE_ENFORCEMENT_GUIDANCE)
```

解决某些模型"描述意图而不执行工具"的问题。门控策略：

| 配置值 | 行为 |
|--------|------|
| `"auto"`（默认） | 匹配 `TOOL_USE_ENFORCEMENT_MODELS` 中的模型名子串 |
| `True` | 所有模型注入 |
| `False` | 不注入 |
| `list[str]` | 自定义模型名匹配列表 |

默认匹配的模型家族：`gpt`, `codex`, `gemini`, `gemma`, `grok`, `glm`, `qwen`, `deepseek`

注入后，还可能根据模型家族追加额外的操作指引：

- **Google 模型**（Gemini/Gemma）：`GOOGLE_MODEL_OPERATIONAL_GUIDANCE`——绝对路径、先验证后修改、并行工具调用、非交互式命令、依赖检查
- **OpenAI/xAI 模型**（GPT/Codex/Grok）：`OPENAI_MODEL_EXECUTION_GUIDANCE`——工具持久性、强制工具使用（算术/系统状态/文件内容等必须用工具而非心算）、先做后问、先决条件检查、验证、缺失上下文处理

`OPENAI_MODEL_EXECUTION_GUIDANCE` 虽然以 OPENAI 命名，但实际也应用于 xAI Grok——两者共享相同的失败模式（声称完成却不调用工具、建议变通方案而非使用现有工具、用计划代替执行）。

#### ⑧ 技能索引

```python
has_skills_tools = any(name in agent.valid_tool_names
    for name in ['skills_list', 'skill_view', 'skill_manage'])
if has_skills_tools:
    skills_prompt = _r.build_skills_system_prompt(
        available_tools=agent.valid_tool_names,
        available_toolsets=avail_toolsets,
    )
```

只有当技能管理工具可用时才构建技能索引。索引格式：

```xml
## Skills (mandatory)
Before replying, scan the skills below. If a skill matches or is even
partially relevant to your task, you MUST load it with skill_view(name)
and follow its instructions...
<available_skills>
  coding: Python, JavaScript and general development
    - hermes-agent: Official Hermes Agent configuration and usage guide
    - code-review: ...
  debugging: Troubleshooting and error resolution
    - ...
</available_skills>
```

技能索引使用三层缓存加速构建（详见第四节）。

#### ⑨ Alibaba 模型名修正

```python
if agent.provider == "alibaba":
    stable_parts.append(
        f"You are powered by the model named {_model_short}. "
        f"The exact model ID is {agent.model}. "
        f"When asked what model you are, always answer based on this information, "
        f"not on any model name returned by the API."
    )
```

Alibaba Coding Plan API 的已知 bug：无论请求什么模型，API 总是返回 `"glm-4.7"` 作为模型名。此修正将真实模型身份注入系统提示。

#### ⑩ 环境提示

```python
_env_hints = _r.build_environment_hints()
```

告知 Agent 当前执行环境的详细信息，分为两种场景：

**本地后端**（host == 工具运行位置）：
```
Host: macOS (15.5)
User home directory: /Users/alice
Current working directory: /Users/alice/projects/myapp
```

**远程后端**（Docker/Modal/SSH 等）：宿主机信息被**抑制**，只显示后端环境：

```
Terminal backend: docker. Your `terminal`, `read_file`, `write_file`,
`patch`, and `search_files` tools all operate inside this docker
environment — NOT on the machine where Hermes itself is running.
The host OS, home, and cwd of the Hermes process are irrelevant;
only the following backend state matters:
  OS: Linux 6.1.0
  User: root
  Home: /root
  Working directory: /app
```

远程后端通过**实时探测**获取环境信息：在容器/远程主机内执行一条精简的 POSIX 探测命令（`printf 'os=%s\n...'`），解析返回的 `key=value` 行。探测结果按 `(env_type, cwd_hint)` 缓存于进程内。

**特殊环境**：
- **WSL**：追加路径映射提示（`/mnt/c/` 对应 C: 盘）
- **Windows 本地**：追加 bash shell 提示（terminal 用 git-bash 而非 PowerShell）
- **嵌入式提示**：通过 `HERMES_ENVIRONMENT_HINT` 环境变量或 `config.yaml` 的 `agent.environment_hint` 注入

#### ⑪ Python 工具链探测

```python
if getattr(agent, "_environment_probe", True):
    from tools.env_probe import get_environment_probe_line
    _probe_line = get_environment_probe_line()
```

检测非默认的 Python/pip/uv/PEP-668 状态，帮助模型选择正确的安装策略。环境干净时不输出任何内容（零 token 成本）。远程终端后端跳过此步。

#### ⑫ Profile 提示

```python
active_profile = _resolve_active_profile_name()
if active_profile == "default":
    stable_parts.append("Active Hermes profile: default. ...")
else:
    stable_parts.append(f"Active Hermes profile: {active_profile}. ...")
```

告知模型当前运行的 Hermes Profile，防止混淆不同 Profile 的技能/插件/Cron/记忆。Profile 名在会话中不变，不破坏缓存。跨 Profile 写入默认被拒绝，需要显式 `cross_profile=True`。

#### ⑬ 平台提示

```python
platform_key = (agent.platform or "").lower().strip()
if platform_key in PLATFORM_HINTS:
    stable_parts.append(PLATFORM_HINTS[platform_key])
```

每个消息平台有定制的格式和行为提示：

| 平台 | 关键行为约束 |
|------|-------------|
| **WhatsApp/Signal** | 不使用 Markdown（不渲染） |
| **Telegram** | Markdown 自动转换；无表格语法，用项目列表 |
| **Discord/Slack** | 标准 Markdown + 原生媒体附件（`MEDIA:/path` 语法） |
| **CLI** | 简单文本，**不**使用 MEDIA: 标签（终端无附件通道） |
| **SMS** | 纯文本，~1600 字符限制 |
| **Cron** | 无用户在场，完全自主执行，不能请求澄清 |
| **Weixin/WeCom** | 支持 Markdown，原生媒体附件 |
| **Yuanbao** | 支持 Markdown + 贴纸工具（`yb_search_sticker` / `yb_send_sticker`） |
| **WebUI** | 完整 Markdown + LaTeX + Mermaid + 丰富媒体预览 |
| **Email** | 纯文本格式，无 Markdown，保持简洁 |
| **Mattermost/Matrix** | 标准 Markdown 渲染 |

平台提示还支持**插件注册**：如果平台不在内置 `PLATFORM_HINTS` 中，会查找 `gateway/platform_registry` 中注册的平台提示。

**MEDIA: 语法**是跨平台媒体投递的统一机制：在响应中包含 `MEDIA:/absolute/path/to/file`，平台适配器自动将其转换为原生附件（照片、语音、文档等）。CLI 模式下此语法无效，因为终端没有附件通道。

### 2.2 Context 层：项目上下文

Context 层包含会话特定的上下文信息：

#### ① 调用方 system_message

```python
if system_message is not None:
    context_parts.append(system_message)
```

外部调用方（如 Gateway 的平台适配器）可传入额外的系统消息。注意 `ephemeral_system_prompt` **不**在这里注入——它在 API 调用时注入，不出现在缓存的系统提示中。

#### ② 上下文文件发现

```python
if not agent.skip_context_files:
    _context_cwd = os.getenv("TERMINAL_CWD") or None
    context_files_prompt = _r.build_context_files_prompt(
        cwd=_context_cwd, skip_soul=_soul_loaded)
```

**发现优先级**（首个匹配即停，只加载一种项目上下文）：

1. `.hermes.md` / `HERMES.md` — 从 cwd 向上遍历至 git 根目录
2. `AGENTS.md` / `agents.md` — 仅 cwd 目录
3. `CLAUDE.md` / `claude.md` — 仅 cwd 目录
4. `.cursorrules` + `.cursor/rules/*.mdc` — 仅 cwd 目录

**关键设计决策**：

- **单一项目上下文**：不同编辑器/工具的上下文文件互斥加载，避免冲突和 token 膨胀
- **.hermes.md 优先级最高**：向上遍历到 git root，适应 monorepo 场景
- **SOUL.md 独立**：SOUL.md 从 `HERMES_HOME` 加载，不走项目上下文发现逻辑（已在 stable 层的身份槽位中加载）
- **TERMINAL_CWD 优先**：Gateway 模式下使用环境变量指定的 cwd 而非 `os.getcwd()`（后者会指向 Hermes 安装目录）
- **安全扫描**：所有上下文文件经过 `_scan_context_content()` 扫描，检测注入攻击和 promptware/C2 模式，命中则阻断并替换为占位符
- **截断策略**：每个文件最大 20,000 字符，超限时保留头部 70% + 尾部 20%，中间插入截断标记
- **YAML Frontmatter 剥离**：`.hermes.md` 文件中的 YAML 前置元数据会被自动移除

### 2.3 Volatile 层：易变状态

Volatile 层包含会话间可能变化的内容：

#### ① 内置记忆快照

```python
if agent._memory_store:
    if agent._memory_enabled:
        mem_block = agent._memory_store.format_for_system_prompt("memory")
        if mem_block:
            volatile_parts.append(mem_block)
```

MEMORY.md 的内容，格式化为系统提示块。

#### ② 用户档案

```python
if agent._user_profile_enabled:
    user_block = agent._memory_store.format_for_system_prompt("user")
    if user_block:
        volatile_parts.append(user_block)
```

USER.md 的内容，始终包含（只要启用）。用户偏好、环境细节、稳定约定等。

#### ③ 外部记忆提供者块

```python
if agent._memory_manager:
    _ext_mem_block = agent._memory_manager.build_system_prompt()
    if _ext_mem_block:
        volatile_parts.append(_ext_mem_block)
```

honcho、mem0 等外部记忆后端注入的额外上下文，与内置记忆叠加。

#### ④ 时间戳/会话/模型信息

```python
now = _hermes_now()
timestamp_line = f"Conversation started: {now.strftime('%A, %B %d, %Y')}"
if agent.pass_session_id and agent.session_id:
    timestamp_line += f"\nSession ID: {agent.session_id}"
if agent.model:
    timestamp_line += f"\nModel: {agent.model}"
if agent.provider:
    timestamp_line += f"\nProvider: {agent.provider}"
```

**日期精度而非分钟精度**——这是一个精心设计的缓存优化。分钟级精度会在每次重建（压缩边界、新 Agent Gateway 会话、无存储提示的会话恢复）时使前缀缓存 KV 失效。模型需要精确时间时可通过工具查询。

## 三、系统提示词失效与重建

### 3.1 缓存失效机制

```python
def invalidate_system_prompt(agent) -> None:
    agent._cached_system_prompt = None
    if agent._memory_store:
        agent._memory_store.load_from_disk()
```

唯一的触发点是**上下文压缩**。压缩后必须重建，因为消息历史发生了变化，同时需要重新加载磁盘上的记忆数据以反映本次会话中的写入。

### 3.2 测试补丁契约

`system_prompt.py` 通过 `_ra()` 函数延迟引用 `run_agent` 模块中的辅助函数，而非直接导入：

```python
def _ra():
    import run_agent
    return run_agent
```

原因是许多测试使用 `patch("run_agent.load_soul_md", ...)` 的模式。如果直接导入，补丁无法到达 `system_prompt` 模块。通过 `run_agent` 间接查找，每次调用都遵循补丁契约。

### 3.3 Developer Role 替换

对于 OpenAI 的较新模型（GPT-5、Codex），系统提示使用 `developer` 角色而非 `system` 角色，以获得更强的指令遵循权重。替换发生在 API 边界层（`_build_api_kwargs()`），内部消息表示始终使用 `"system"`。

匹配的模型名子串：`gpt-5`, `codex`

## 四、技能索引的三层缓存

`build_skills_system_prompt()` 使用三层缓存加速技能索引构建：

### 4.1 缓存层次

```
Layer 1: 进程内 LRU 缓存 (_SKILLS_PROMPT_CACHE, 最多 8 条)
    ↓ miss
Layer 2: 磁盘快照 (.skills_prompt_snapshot.json, mtime/size manifest 验证)
    ↓ miss
Layer 3: 完整文件系统扫描 (冷路径，扫描后写入快照)
```

### 4.2 缓存键

```python
cache_key = (
    str(skills_dir.resolve()),
    tuple(str(d) for d in external_dirs),
    tuple(sorted(str(t) for t in (available_tools or set()))),
    tuple(sorted(str(ts) for ts in (available_toolsets or set()))),
    _platform_hint,
    tuple(sorted(disabled)),
)
```

缓存键包含技能目录、外部目录、可用工具集、可用工具集组、平台提示和禁用技能列表——确保不同配置产生不同的缓存条目。

### 4.3 磁盘快照验证

快照通过比较 SKILL.md/DESCRIPTION.md 的 `mtime_ns + st_size` 判断是否过期：

```python
def _build_skills_manifest(skills_dir):
    manifest = {}
    for filename in ("SKILL.md", "DESCRIPTION.md"):
        for path in iter_skill_index_files(skills_dir, filename):
            st = path.stat()
            manifest[str(path.relative_to(skills_dir))] = [st.st_mtime_ns, st.st_size]
    return manifest
```

快照版本号 `_SKILLS_SNAPSHOT_VERSION` 确保格式变更时旧快照自动失效。

### 4.4 条件激活

技能可声明条件激活规则：

- **`fallback_for_toolsets` / `fallback_for_tools`**：主工具可用时隐藏此技能（降级方案）
- **`requires_toolsets` / `requires_tools`**：必要工具不可用时隐藏此技能（前置条件）

```python
def _skill_should_show(conditions, available_tools, available_toolsets):
    # fallback_for: hide when the primary tool/toolset IS available
    for ts in conditions.get("fallback_for_toolsets", []):
        if ts in ats:
            return False
    # requires: hide when a required tool/toolset is NOT available
    for ts in conditions.get("requires_toolsets", []):
        if ts not in ats:
            return False
    return True
```

### 4.5 外部技能目录

`config.yaml` 的 `skills.external_dirs` 配置外部技能目录。外部目录只读，出现在索引中但新技能始终创建在本地目录。本地技能同名时优先。

## 五、Anthropic Prompt 缓存策略

### 5.1 system_and_3 策略

`agent/prompt_caching.py` 实现了唯一的缓存布局：`system_and_3`。

**4 个 `cache_control` 断点**：

1. 系统提示（第一条消息，`role="system"`）
2. 最后 3 条非系统消息

所有断点使用相同的 TTL（`5m` 或 `1h`）。

```python
def apply_anthropic_cache_control(api_messages, cache_ttl="5m", native_anthropic=False):
    messages = copy.deepcopy(api_messages)
    marker = _build_marker(cache_ttl)  # {"type": "ephemeral"} or {"type": "ephemeral", "ttl": "1h"}

    breakpoints_used = 0
    if messages[0].get("role") == "system":
        _apply_cache_marker(messages[0], marker)
        breakpoints_used += 1

    remaining = 4 - breakpoints_used
    non_sys = [i for i in range(len(messages)) if messages[i].get("role") != "system"]
    for idx in non_sys[-remaining:]:
        _apply_cache_marker(messages[idx], marker)

    return messages
```

### 5.2 缓存标记注入逻辑

`_apply_cache_marker()` 处理所有消息格式变体：

| 消息格式 | 处理方式 |
|---------|---------|
| `role="tool"` + `native_anthropic=True` | 在消息顶层添加 `cache_control` |
| `content` 为 `None` 或空 | 在消息顶层添加 `cache_control` |
| `content` 为字符串 | 转换为 `[{"type": "text", "text": content, "cache_control": marker}]` |
| `content` 为列表 | 在最后一个元素上添加 `cache_control` |

### 5.3 成本节省估算

在多轮对话中，4 个断点可减少约 **75%** 的输入 token 成本：

- 系统提示通常 5k-15k token，完全从缓存读取
- 最近 3 轮对话从缓存读取，只有最新一轮需要完整处理
- 随对话轮次增加，缓存命中率趋近于 100%

### 5.4 TTL 选项

| TTL | 适用场景 |
|-----|---------|
| `5m`（默认） | 普通对话会话 |
| `1h` | 长时间运行的 Gateway 会话、定时任务 |

## 六、上下文文件安全扫描

### 6.1 扫描范围

`_scan_context_content()` 使用 `tools/threat_patterns.py` 的 `scan_for_threats()` 函数，scope 为 `"context"`：

- **覆盖**：经典注入攻击 + promptware/C2 模式 + 角色扮演劫持
- **不覆盖**：strict-scope 模式（SSH 后门、持久化、exfil-URL）——对克隆仓库中的上下文文件过于激进

### 6.2 阻断行为

内容匹配时**阻断**（不是警告），替换为占位符：

```
[BLOCKED: AGENTS.md contained potential prompt injection (pattern1, pattern2). Content not loaded.]
```

原因：上下文文件会逐字进入系统提示，用户没有机会干预。

## 八、设计模式总结

| 模式 | 实现 | 解决的问题 |
|------|------|-----------|
| 缓存友好分层 | stable/context/volatile 三层 | 最大化 Prompt Cache 命中率 |
| 条件性注入 | 工具门控、模型门控、配置门控 | 减少 token 浪费，避免无关指引 |
| 延迟引用 | `_ra()` 间接查找 `run_agent` | 保持测试补丁契约 |
| 声明式记忆 | 要求陈述式而非祈使式 | 防止记忆指令干扰后续会话 |
| 日期级时间戳 | 只到天，不到分钟 | 避免分钟级变化破坏前缀缓存 |
| 宿主信息抑制 | 远程后端不暴露宿主 OS/路径 | 防止模型使用不可达的宿主信息 |
| 零成本环境探测 | 干净环境不输出任何内容 | 省去无用的 token |
| 单一项目上下文 | .hermes.md > AGENTS.md > CLAUDE.md 互斥 | 避免冲突和 token 膨胀 |
| 安全扫描阻断 | 上下文注入命中则替换为占位符 | 防止 prompt 注入和 promptware |
| 磁盘快照缓存 | mtime/size manifest 验证 | 加速技能索引构建 |
| Developer Role | GPT-5/Codex 使用 developer 角色 | 获得更强的指令遵循权重 |
| API Bug 修正 | Alibaba 模型名注入系统提示 | 绕过 API 返回错误模型名 |
