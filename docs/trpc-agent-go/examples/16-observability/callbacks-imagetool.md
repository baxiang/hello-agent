# 图像工具回调（Imagetool）- 把二进制图片转成多模态消息

> **源码路径**：[`trpc-agent-go/examples/callbacks/imagetool/`](../../../../trpc-agent-go/examples/callbacks/imagetool)
> **示例类型**：单次执行 · **难度**：进阶

## 概述

`imagetool/` 子示例演示回调家族里**与 Before/After 完全不同**的一类钩子：`ToolResultMessages`。它的职责是把普通函数工具返回的**原始 PNG 字节流**，转换成 OpenAI 兼容协议能消费的"工具消息 + 用户图片消息"组合，让支持视觉的 LLM 能"看到"工具生成的图。

与兄弟示例的差别：

| 示例 | 改的是 |
|------|--------|
| [`basic`](./callbacks-basic.md) | 输入参数 / 响应文本 |
| [`auth`](./callbacks-auth.md) | 执行流（拒绝）+ State |
| [`timer`](./callbacks-timer.md) | 旁路观测（OTEL） |
| **本文（imagetool）** | **回传给模型的消息形状本身** |

## 核心概念

### 默认工具消息 vs 多模态消息

trpc-agent-go 默认把工具结果序列化成一个 `role: "tool"` 的 JSON 文本消息回传给模型：

```
assistant: [tool_call id=call_1] demo_image_tool(...)
tool      : {"title":"...","data":"<base64>","format":"png"}   ← 默认只有这一条
```

但 JSON 字符串里的图片对模型毫无意义——模型不会去解码 base64。要让模型真正"看见"图，必须再追加一条**携带 `image_url` 的 `role: "user"` 消息**：

```
assistant: [tool_call id=call_1] demo_image_tool(...)
tool      : {"title":"...","data":"...","format":"png"}
user      : [ContentParts: text + image]   ← ToolResultMessages 追加的多模态消息
```

这正是 `ToolResultMessages` 钩子要干的事。

### ToolResultMessages 回调签名

```go
func(ctx context.Context, in *tool.ToolResultMessagesInput) (any, error)
```

`ToolResultMessagesInput` 的关键字段：

| 字段 | 含义 |
|------|------|
| `ToolName` | 当前工具名 |
| `ToolCallID` | 当前 `tool_call` 的唯一 ID（每次调用触发一次回调） |
| `Result` | 工具实际返回的结果（类型断言回业务结构体） |
| `DefaultToolMessage` | 框架默认生成的 `model.Message`（`role: "tool"`） |

返回值可以是 `model.Message` 或 `[]model.Message`，框架只做类型检查与 Choices 包装。

### 三条铁律

1. **每次调用只处理一个 tool_call**：以 `in.ToolCallID` 为作用域，不要把多个结果混到一个 slice 里
2. **必须保留至少一条 `role: "tool"` 消息**：OpenAI 兼容协议要求 `assistant(tool_calls)` 后面紧跟 `role: "tool"` 且 `tool_call_id` 匹配，否则返回 4xx
3. **图片给真实字节，不要二次 base64**：`model.Image{Data: pngBytes}`，OpenAI 适配器会负责编码成 `image_url`

### 注册方式

```go
toolCallbacks := tool.NewCallbacks()
toolCallbacks.RegisterToolResultMessages(toolResultMessagesCallback)

agent := llmagent.New("imagetool-agent",
    llmagent.WithTools([]tool.Tool{imageTool}),
    llmagent.WithToolCallbacks(toolCallbacks),
)
```

> 如果回调返回 `nil` 或空 slice，框架回退到默认行为（只发 JSON 工具消息）——**完全向后兼容**。

## 代码解析

### 文件结构

示例刻意做得极简：只有一个 `main.go`，把工具、回调、Runner 全部塞进去，方便聚焦在回调本身。

### 工具：生成 PNG 字节

`generateDemoImage` 是个普通函数工具，**对 OpenAI 协议一无所知**，只负责返回 PNG 字节流：

```go
func generateDemoImage(_ context.Context, args *imageToolArgs) (*imageToolResult, error) {
    const width, height = 64, 64
    img := image.NewRGBA(image.Rect(0, 0, width, height))
    bg := color.RGBA{R: 34, G: 139, B: 230, A: 255}   // 蓝色填充
    for y := 0; y < height; y++ {
        for x := 0; x < width; x++ {
            img.Set(x, y, bg)
        }
    }
    var buf bytes.Buffer
    png.Encode(&buf, img)
    return &imageToolResult{
        Title:  labelOr(args.Label, "A demo PNG image generated by demo_image_tool."),
        Data:   buf.Bytes(),
        Format: "png",
    }, nil
}
```

返回结构：

```go
type imageToolResult struct {
    Title  string `json:"title"`
    Data   []byte `json:"data"`
    Format string `json:"format"`
}
```

### 回调：把 PNG 包装成多模态消息

```go
func toolResultMessagesCallback(ctx context.Context, in *tool.ToolResultMessagesInput) (any, error) {
    // 1) 只处理目标工具，其他工具走默认
    if in.ToolName != "demo_image_tool" {
        return nil, nil
    }

    // 2) 取出工具结果
    result, ok := in.Result.(*imageToolResult)
    if !ok || result == nil || len(result.Data) == 0 {
        return nil, nil
    }

    // 3) 保留框架默认生成的 role:tool 消息
    defaultMsg, ok := in.DefaultToolMessage.(model.Message)
    if !ok {
        return nil, nil
    }

    // 4) 构造一条 role:user 消息，含 text + image 两个 ContentPart
    text := result.Title
    imagePart := model.Image{Data: result.Data, Format: result.Format}
    parts := []model.ContentPart{
        {Type: model.ContentTypeText,  Text:  &text},
        {Type: model.ContentTypeImage, Image: &imagePart},
    }
    userMsg := model.Message{
        Role:         model.RoleUser,
        ContentParts: parts,
        ToolID:       in.ToolCallID,    // 关键：关联到当前 tool_call
    }

    // 5) 同时返回原 tool 消息 + 新 user 图片消息
    return []model.Message{defaultMsg, userMsg}, nil
}
```

关键点：

- `ToolID: in.ToolCallID`：把追加的 user 消息与触发它的 tool_call 关联起来
- 顺序 `[defaultMsg, userMsg]`：先 tool 后 user，符合 OpenAI 协议预期
- `imagePart.Data` 是真实 PNG 字节，**不要**预先 base64

### Runner 接线

```go
genConfig := model.GenerationConfig{Stream: false}   // 非流式便于演示
agent := llmagent.New("imagetool-agent",
    llmagent.WithModel(llm),
    llmagent.WithInstruction("First call demo_image_tool, then describe the image you received."),
    llmagent.WithGenerationConfig(genConfig),
    llmagent.WithTools([]tool.Tool{imageTool}),
    llmagent.WithToolCallbacks(toolCallbacks),
)

r := runner.NewRunner("imagetool-runner", agent,
    runner.WithSessionService(inmemory.NewSessionService()),
)
defer r.Close()

msg := model.NewUserMessage("First call demo_image_tool to generate an image, then describe what is in the image.")
events, _ := r.Run(ctx, "demo-user", "session-imagetool", msg)
```

指令显式要求"先调用工具、再描述图片"，让模型自主走完"调用 → 接收图片 → 描述"的全链路。

## 运行方式

### 环境变量

| 变量 | 必需 | 说明 |
|------|------|------|
| `OPENAI_API_KEY` | 是 | 模型 API Key |
| `OPENAI_BASE_URL` | 否 | 模型端点（OpenAI 兼容代理） |
| `MODEL_NAME` | 否 | 默认模型名（仅当未传 `-model` 时使用） |

### 命令行参数

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `-model` | 模型名 | 读 `MODEL_NAME` 环境变量；若仍为空则用 `gpt-4.1-mini` |

> 本示例需选用**支持视觉输入**的模型（如 `gpt-4.1`、`qwen3-omni-30b-a3b-thinking` 等），否则模型会忽略图片消息。

### 运行命令

```bash
cd examples                # 注意：从 examples 目录运行
export OPENAI_BASE_URL="your-openai-compatible-base-url"
export OPENAI_API_KEY="your-api-key"
export MODEL_NAME="gpt-4.1"

go run ./callbacks/imagetool
```

## 适用场景与对比

**选 imagetool 当：**
- 工具会产出图像、PDF、音频等**非文本**数据，需要让多模态模型"看见"
- 想保留 OpenAI 兼容的 function calling 协议，又不想自己重写消息构造
- 已有 MCP 工具或 function tool 返回二进制，希望最小改动接入视觉模型

**对比兄弟示例：**

| 维度 | imagetool | basic | auth | timer |
|------|-----------|-------|------|-------|
| 回调类型 | `ToolResultMessages` | Before/After 全套 | Before/After | Before/After |
| 干预时机 | 工具完成后、消息回传前 | 全链路 | 工具前/后 | 全链路 |
| 改的对象 | 回传的消息形状 | 参数 / 响应文本 | 执行流 + State | 旁路（OTEL） |
| 模型要求 | 必须多模态 | 任意 | 任意 | 任意 |

### 移植到自己项目的步骤

1. 工具返回结构体里加一个 `[]byte` 字段承载原始二进制
2. 注册 `ToolResultMessages` 回调，按 `in.ToolName` 分流
3. 回调里：保留 `in.DefaultToolMessage`，再 append 一条带 `ContentParts` 的 `RoleUser` 消息
4. `model.Image{Data, Format}` 给真实字节，编码交给 OpenAI 适配器

## 关键要点

1. **`ToolResultMessages` 是和 Before/After 并列的第三类工具回调**：专门用于改写"工具结果回传给模型的消息"
2. **协议合规自负其责**：框架只做类型检查与 Choices 包装，`Role` 与 `ToolID` 必须自己设对
3. **必须保留至少一条 `role: "tool"` 消息**：否则 OpenAI 兼容协议会 4xx
4. **以 `ToolCallID` 为作用域**：每次回调只处理当前 tool_call 的结果
5. **图片给真实字节**：`model.Image{Data: pngBytes, Format: "png"}`，不要预先 base64
6. **不注册就回退**：未注册或返回 `nil` 时完全等价于旧行为

## 总结

imagetool 示例展示了回调系统的另一种力量：除了"拦截"和"观测"，还能**重塑协议消息**。同样的模式可扩展到音频、视频、文件附件等任何多模态载荷。若想了解 Before/After 回调的全景，回到 [`basic`](./callbacks-basic.md)；若想看回调与可观测体系的深度结合，看 [`timer`](./callbacks-timer.md)。回到 [`callbacks`](./callbacks.md) 索引页可查看完整导航。
